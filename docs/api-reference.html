Autentificare

Se foloseste o singura cheie globala, trimisa in headerul X-Api-Key (se accepta si Authorization: Bearer <cheie>).

Cheia se genereaza din Setari → Integrare (cu ApiEnabled = DA). Se afiseaza o singura data; in baza de date se pastreaza doar SHA-256.

curl -s -H "X-Api-Key: tm_..." http://<statie>/rual/api/v1/version
Eroare 401 fara cheie/gresita, 403 IP nepermis, 429 peste limita, 503 API dezactivat.

Format raspuns

Succes:

{ "status": "success", "data": { ... }, "meta": { ... } }

Eroare:

{ "status": "error", "message": "..." }

Paginare

Parametri: ?limit= (implicit 100, maxim 500) si ?offset= (implicit 0). meta contine limit, offset, count, hasMore (si total unde exista).

Coduri de eroare

CodInteles
400Cerere invalida (camp obligatoriu lipsa etc.)
401Cheie API lipsa sau invalida

Acces extern (VPN)

Aplicatia ruleaza pe HTTP si nu se expune pe internet. Accesul din exterior se face exclusiv prin VPN. Recomandat SoftEther VPN Azure + SecureNAT (hostname vpn…vpnazure.net, API accesat la IP-ul virtual, ex. http://192.168.30.1/rual/api/v1/); alternativ Tailscale / ZeroTier. Setati ApiAllowedIps pe subreteaua virtuala a VPN-ului. SoftEther se descarca de la softether.org/5-download.

GET/groups

Lista grupe. Obiect grupa: nrGrp, denumire, poz, backColor, fontColor, fontSize, fontType, bold.

GET/tables

Cele 80 de mese. Obiect masa: nrMasa, isOccupied, present, casier, nrOp, total, docId, backColor, foreColor, bold, afisez.

GET/orders ?stare=D|I?from=?to= ?source=current|archive?limit=?offset=

Lista bonurilor. source=current (implicit) = sesiunea curenta; archive = dupa raportul Z. from/to sunt date (YYYY-MM-DD), to exclusiv pana la finele zilei.

Obiect antet bon (BillHeader): docId, nrDoc, nrZ, data, ora, nrMasa, nrOp, casier, stare, total, magId, clientId, codFiscBon, source.

GET/orders/{docId} ?source=current|archive

Un bon: antet + lines[] + payments[].

Linie (OrderLine): ecrId, prodId, denumire, cantitate, pretUnitar, pvc, valoare, valoareOriginala, tva, comment, stornoRef, isModifier (mod preparare), isStorno (anulare).

Plata (Payment): fpid, denumire, suma.

GET/events ?since=?limit=

Flux incremental de bonuri inchise (pentru polling). Returneaza bonurile cu DocID > since (sesiunea curenta + arhiva). Retineti meta.nextSince si trimiteti-l la urmatoarea cerere.

{ "status":"success", "data":[ { "docId":1043, ... } ],
  "meta": { "since":1042, "nextSince":1043, "count":1, "hasMore":false } }

Import (POST)

Corpul accepta un singur obiect, un { "items": [ ... ] } sau un array de obiecte. Scrierea se face in tranzactie. Pentru reincercari sigure trimiteti headerul Idempotency-Key: acelasi POST cu aceeasi cheie intoarce raspunsul original fara a re-executa scrierea. Raspuns de succes: { "status":"success", "data":{ "saved": N } }.

Importul de produse/grupe este refuzat cu 409 cand setarea Server este activa (tblSet.Server = 1): meniul este administrat de serverul extern prin dbo.ImportProd, iar importul local este blocat. Raspunsul documenteaza cauza (code: "server_managed", setting: "Server", value: 1, resource). Pentru a permite importul prin API, setati Server = NU in Setari → General. Celelalte importuri (tables, waiters, payment-forms, vat) nu sunt afectate.
